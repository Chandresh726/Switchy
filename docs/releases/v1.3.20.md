# Switchy v1.3.20

Fixes the scraper slowdown caused by Workday tasks occupying worker capacity
while waiting for a shared lock and by large first-run description refreshes.

- Admits one Workday company at a time before leasing work. Other Workday tasks
  remain queued, allowing faster platforms to proceed. Same-company work across
  sessions also waits without consuming a worker lease.
- Bounds optional description maintenance to five existing jobs per company and
  25 per session. A six-hour company cooldown and staggered freshness eligibility
  spread maintenance across runs, with capacity reserved for waiting companies.
  New jobs and missing or teaser descriptions
  retain priority.
- Preserves saved descriptions and unknown legacy freshness. Maintenance quotas
  survive restarts without a schema migration.
- Records internal queue, lock, HTTP, pacing, retry, and refresh metrics so future
  runs can be diagnosed without treating lock waiting as network time.

Workday pacing, cooldowns, browser limits, incomplete-listing protection, and
atomic job persistence remain in place. The settings UI is unchanged.

Validation includes a 151-company scheduling regression, complete cold-start
Workday ingestion through injected clients, shared-budget persistence, and
request-metric isolation. Production timing gains will depend on source latency
and will be measurable in subsequent scrape runs.
