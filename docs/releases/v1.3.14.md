# Switchy v1.3.14

Speeds up job browsing and dashboard loading, reduces repeated history reads, and simplifies match storage.

- Uses one preferred-match selection rule for sorting, summaries, and details. Score-sorted lists select a narrow page before loading job data, and summaries skip evidence parsing.
- Shares match context across dashboard sections and avoids exact counts for preview lists. People search is debounced and uses a compact summary request.
- Queues manual company refreshes immediately and tracks their completion through durable sessions. Compact progress polling refreshes details when progress changes and slows down during retry cooldowns.
- Paginates writing-history summaries and loads generation telemetry on demand.
- Moves person source-record backfills out of GET requests and adds indexed canonical company URL lookups.
- Removes five obsolete match columns from jobs, retaining versioned match results as the source of scores. Generated migrations preserve job IDs and application state.
- Adds API timing and query-count headers and a repeatable `pnpm benchmark:api` command that uses a disposable database snapshot.

Validation includes the full workspace verification gate with 1,378 tests, database upgrade coverage, and two migration runs against a populated disposable snapshot.

## API changes

- `POST /api/companies/refresh-jobs` returns `202 Accepted` with `sessionId`, `status`, and `totalCompanies`; completion is available through scrape-session progress and history.
- `GET /api/ai/history` accepts `limit` and `offset` and returns summaries with pagination. `GET /api/ai/history/[id]` returns full writing details.
- Job-list callers can request `includeTotal=false` to skip exact counts. In that mode, `totalCount` is `null` and `hasMore` remains available.

The bundled application and typed clients use these contracts together. Existing substring search and numbered job-list pagination are preserved.
