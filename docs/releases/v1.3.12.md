# Switchy v1.3.12

Simplifies shared contracts, Settings, scraper execution, and matcher reads while preserving the local-first application layout.

- Shares provider model validation across server catalogs, API responses, and CLI caches. Centralizes company platform definitions, URL detection, and display metadata.
- Moves application error classes out of the HTTP layer so services and API handlers use the same errors.
- Separates Settings provider management and model reconciliation from the page. Shares AI feature setting keys with backend normalization and reads one settings snapshot per update.
- Moves shared queue execution, dispatch, locks, maintenance gates, and sleep protection into the common runtime. Keeps AI and scraper rate-limit policies with their domains.
- Uses one scraper failure classifier for adapters and pipeline exceptions, including retry hints, timeouts, cancellation, and terminal error logging.
- Removes matcher and CLI dependency loops, a duplicate profile fetch during AI writing, an obsolete profile type, and duplicate filter-chip code.
- Removes unused assets and redundant tests, consolidates fixtures, expands dead-code checks, and ignores generated reports.
- Retries exact-version npm installation verification during registry propagation so a successful publication does not immediately produce a false failure notification.

- Builds the macOS ARM64 runtime on GitHub's macOS 26 image. The v1.3.11 candidate was not published because GitHub could not allocate its macOS 15 runner after two attempts.

No database schema changes or user-data migrations are introduced.
